Copies that keep the rules: protected, or not made

This autumn, four copies of the learners' records are asked for: one to build with, one for the teaching hospital, an answer that needs both sides' rows, and one to take home. The rules live in the catalog, not in the records, so each copy keeps the protection, or isn't made.

Read the guidance yourself

The film shows Azure Databricks and dbt as their docs did on 10 November 2026. These are the pages it follows.

  • Azure Databricks: OpenSharing and ABACWhy whoever shares a protected table must be left out of its policies, and why the recipient then sees every value unless it applies policies of its own.
  • Azure Databricks: requirements and limits of policiesClones of a table with policies aren't allowed, except for someone every policy leaves out, who sees every value unmasked.
  • Azure Databricks: what is Clean Rooms?Partners work together on sensitive data without seeing each other's rows: each sees only the other's column names and types.
  • Azure Databricks: run notebooks in clean roomsEvery collaborator but the one who uploaded it approves a notebook before it runs, and only the runner it names may run it.
  • Azure Databricks: manage access to notebook featuresThe workspace's switches for downloading results, exporting notebooks and copying tables to the clipboard, which start switched on.
  • Azure Databricks: serverless egress controlA network policy that lets what runs on serverless compute reach only the catalog's storage and the places on a short list.
  • dbt: unit testsTesting a model's logic on a few rows written for the test, so no real data is needed to check it.
