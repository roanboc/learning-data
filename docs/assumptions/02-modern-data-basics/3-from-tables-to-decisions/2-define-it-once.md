## Rodrigo's answer of 12 November 2026: where a measure is defined

Question 5 was the one put to Rodrigo for this film: *is "one home per measure, by where its readers are" the rule you'd teach, or should one semantic layer hold them all?* His answer, on 12 November 2026:

> Define it once. In one place is fine, ideally in an agnostic layer like Ossie and then from there implemented in the tool (also ideally one, but that depends on the org context), but at least having them clearly catalogued.

"Ossie" is read as Apache Ossie, the open format the film already names in *A format any tool can read*. It was called the Open Semantic Interchange (OSI) until July 2026, so both names are one standard. Question 5 is closed: one home per measure stands. The film now also says the three things it didn't, a line each, made in the thread "Apply review answers to Modern data basics" (PR #PRNUM):

| His words | The film's line now | Where it shows |
|---|---|---|
| "In one place is fine" | Unchanged in meaning: "So each measure gets one home, near most of its readers, and is never defined twice." | Chapter 5 |
| "also ideally one, but that depends on the org context" | "One tool for every measure is simplest, but that depends on the organisation: this university uses both." Finance's casual teaching cost sits over a metric view and Planning's learners near a graduate certificate over MetricFlow, with "one tool is simplest" and "it depends on the organisation" between them. | Chapter 5; the second Pause and think question's explanation |
| "ideally in an agnostic layer like Ossie and then from there implemented in the tool" | "Ideally, the definition is written in Ossie first, in the data project, and the metric view is built from it."
