The films

Watch them in order. It's technical: it shows real code, YAML and Markdown from an example dbt project that runs on dbt Core with DuckDB, in this site's repository, so you can run it yourself. It makes most sense after From words to data.

  1. 1Declare it, then build it5½ min · dbt calls every query a model. The data model is the blueprint: declared beside the code, and checked by the tests.
  2. 2Start from a question5 min · A model has no edge until a question gives it one. Model only what the question touches, and name who owns each meaning first.
  3. 3What makes it the same one4½ min · One learner, three keys, and a look-alike. Rules match most of them; a person decides the rest, and the decision becomes data and a test.
  4. 4One row of what, and when5 min · Twelve on census day, nine today: both right. Say what one row is and which day it describes, before any SQL, and test both.
  5. 5Promises and proofs5½ min · Every gap gets a decision. Promise it in a contract; prove it with a test, written before the code it checks.
  6. 6Built in layers4½ min · Four layers turn the tests green. Each layer has one job; each CTE, one step; and the rule is written once.
  7. 7Who owns what5½ min · Each fact's meaning has an owner. Owners publish a public, versioned core; consumers build on it, never on each other's marts.
  8. 8An agent on the team5½ min · An AI agent drafts in minutes. It follows rules written in the project, shows the query behind every claim, never weakens a test, and people approve.
  9. 9Written once5½ min · Every copy of a fact is a chance to drift. One home per fact, everything else generated, and a breaking change arrives as a new version with a date.
  10. 10End to end8½ min · One question, ten steps, ten commits. Every file in its place, for as long as it's needed.
