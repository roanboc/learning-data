Cargas sin secretos: un proceso que prueba quién es

Cada noche a las dos, un proceso carga los datos del registro, y aún corre con el token personal de Jun Park, con copias en su configuración, en un notebook en GitHub y en su laptop. ¿Cómo puede probar quién es cada vez que corre, sin nada que alguien pueda copiar?

Las páginas oficiales detrás de cada paso que muestra la película, de Microsoft y GitHub.

  • Azure Databricks: entidades de servicioUna identidad para un proceso o una herramienta, no para una persona, y por qué un proceso debe correr como una.
  • Azure Databricks: federación de identidades de carga de trabajo para GitHub ActionsCómo un flujo de trabajo entra con una nota que GitHub firma en cada ejecución, comparada con una directiva, sin guardar ningún secreto.
  • Microsoft Entra ID: identidades administradas para recursos de AzureUna identidad que Azure le da a un recurso, cuyas credenciales Azure guarda y cambia, y nadie ve.
  • Azure Databricks: administración de secretosÁmbitos de secretos respaldados por Azure Key Vault, quién puede leerlos, y por qué un secreto impreso aparece como redactado.
  • GitHub: acerca del análisis de secretosCómo GitHub lee toda la historia de un repositorio en busca de secretos, comprueba si aún funcionan y crea una alerta.
  • GitHub: acerca de la protección de inserciónCómo se detiene una inserción con un secreto antes de que llegue, y qué hace falta para pasarla por alto.
