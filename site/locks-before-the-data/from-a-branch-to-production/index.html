The film shows GitHub and Databricks as their docs did on 5 November 2026. These are the pages it follows, and the list of what goes wrong in a path to production.

  • GitHub: managing environments for deploymentRequired reviewers, Prevent self-review, deployment branches, and why administrators shouldn't bypass them.
  • GitHub: available rules for rulesetsPull requests, code owners' reviews, the last push approved by someone else, status checks, and the bypass list.
  • GitHub: about code ownersWho is asked to review, and why the file on the base branch decides it.
  • GitHub: secure use referencePinning actions to a full commit; workflow dependency lockfiles, which also pin the actions an action calls; and keeping the workflow's token to the least it needs.
  • GitHub: keeping your actions up to date with DependabotHow Dependabot proposes new versions of actions pinned to a commit, as pull requests.
  • Databricks: deployment modes for bundlesDevelopment mode's own copies, and production mode, deployed from one branch by a service principal.
  • Databricks: workload identity federation for GitHub ActionsA federation policy whose subject names one environment, so only that environment's job signs in.
