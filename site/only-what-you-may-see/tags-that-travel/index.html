Tags that travel: a class set once, carried everywhere

Mei has named a class for every column of the learner table. The platform has to read them, and every table made from it has to carry them, or a copy shows what its source hides. How do the classes become tags in Databricks and dbt, and follow the data on their own?

Read the guidance yourself

The film shows Azure Databricks, dbt and GitHub as their docs showed them in November 2026. These are the pages it follows.

  • Governed tagsAzure Databricks: a tag with its allowed values and a policy for who may assign it, so only those values are set, only by those allowed.
  • Tag propagationAzure Databricks: a governed tag carried through lineage to the tables and views made from a tagged column, and the default value applied where two values meet.
  • Data ClassificationAzure Databricks: a scan of chosen catalogs that proposes classes for the columns it recognises, such as a name or an email, for their owners to confirm.
  • Lineage in Unity CatalogAzure Databricks: the platform's record of what each query read and what it made, down to the column, which tag propagation follows.
  • metadbt: the meta config, where the project writes each column's class beside it, in the model's YAML file.
  • pre-hook & post-hookdbt: SQL run before or after a model builds, as the project's hooks set each class, the faculty tag and the level after every build.
