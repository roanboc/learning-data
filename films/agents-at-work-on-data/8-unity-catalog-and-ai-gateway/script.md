## The promise

Every line passes two tests: someone who has never opened a data platform can follow it, and a platform engineer or a security lead finds nothing wrong in it. *Working with agents on Databricks* gave every agent the same governed data and tools people use, and left one question: when an agent reads on its own, whose reads are they, and who pays for its model? This film answers it. An agent that runs on a person's own key gets everything that person can do, its model calls come from no one's budget, and the log can't tell its reads from his. Given a name of its own, a service principal, an agent sits under the rules people already work under, kept where the data and the models live: in Unity Catalog, only the grants its job needs, the same masks and row filters, its tools as functions it may run and can't change, and its reads in the log and in lineage; in Unity Gateway, part of the catalog, the models and tool servers it may call, checks on what goes in and out, a limit on how fast it calls, and every call counted under its name. A rule an agent is told is a request; a rule the platform enforces holds, whatever the agent is told. **One set of rules for people and agents, enforced where the data and the models live.**

## The story in one paragraph

Today, at the university. Every week, the Faculty of Health's heads of school ask the same questions: how many teach this term, and how many are casual. So Anil Kurian, who runs the faculty's office, set up an agent that answers them at night, on its own, in an afternoon, with his personal key, a code that lets software sign in as him. Each month, Sam Okafor, who runs the data platform, checks the platform's log of who read the staff table, with every staff member's name, birth date and email: one Sunday night, Anil read it 2,300 times. He was asleep; the reads were his agent's. Acting as him, it could read everything he can, though all it needed was counts; a cleverly worded question could have tricked it into handing names over; it called its model with another key of his, paid from no one's budget, and no one saw what the calls carried; and if names ever leaked, the log would point at Anil. He did nothing wrong: a personal key can't hand over less than everything he has. Something had to change. So Sam gives the agent a name of its own, under the same rules as people: Unity Catalog gives it only the grants its job needs, and stars where the names are; Unity Gateway lets it call only the models it's allowed, and counts what it spends. It worked: the heads of school get the same answers every morning, the agent hasn't seen a single name since, its calls cost about 300 dollars a month from the faculty's own budget, and the log says whose reads they were. Jun's project check agent, which checks each night's count of research projects, works the same way. Then the film asks why both: the project's page for agents already says never to copy names into a prompt, but a rule an agent is told is a request it can misread, lose or be talked out of, while a rule the platform enforces holds. It shows the two places that keep the rules (Unity Catalog for what agents touch, Unity Gateway for the models and tool servers they call); a name for the agent, a person's sign-in only while it helps that person, otherwise a service principal with only the grants its job needs, the workload agent, which Sam can switch off without stopping anyone else, and Anil still its owner; the same policy that shows Clara stars showing the agent stars, because the account's users include every service principal, the same for a row filter, and the staff code readable for counting, so the workload agent counts each school's teachers without a single name; its tools in the catalog, the count of active projects the data team wrote once as a function an agent may run and can't change, and tool servers registered through Unity Gateway, each with its own grant; its models as services only those granted can call, with checks that hide an email address in a prompt or look for words written to trick it, a limit on its calls, and every call counted under its name; and Sam's log a month later, where Anil's reads and the agent's are apart, with lineage and the gateway's own table beside it. Rules kept there hold for every agent, every tool and every person, and they're the rules people already work under: one set to keep, one log to read, one review. The count Anil plans lab space from, 168 projects, is checked by an agent the team can see, limit and account for.

**Where the film adopts, extends or differs.** It adopts the platform's model as its docs give it: one catalog that governs data, functions, models and tool servers by the same grants. It extends it with the module's rules from practice: tool servers get the fewest rights (the workload agent's only read), an agent always has a human owner, and nothing reaches production without a person. It differs from a reading of the docs that would make the agent's instructions enough: the project's page for agents still tells it the rules (*An agent on the team*), and the film says to do both, tell the agent and enforce the rules where the data and the models live.

**Practice, from the author (the plan's insights):** an agent in the wrong hands is more dangerous; tool servers get the fewest rights, read only when reading is enough, and no sensitive data; memory and context are shared by the team (the next film); agents are never approvers. A practitioner will recognise the opening: an agent built in an afternoon on someone's personal token, which works, and which nobody can see apart from the person whose token it is. Databricks itself calls personal access tokens a legacy way to sign in and recommends OAuth "because OAuth provides stronger security".

**What the film leaves to its siblings and the later series.** How an agent earns its own identity, step by step, with a GitHub App and no secret, is *From helper to colleague*'s (its *An agent with its own badge*); watching each agent's work and cost on one page, with a budget that stops it, is *A colleague that isn't a person*'s. ## Sound

**The palette, its own** (the series' `palettes.md`, 4 November 2026, where the series thread reserved its lead; checked against every `score.py` on main): an **electric clavichord**, the 1960s keyboard whose keys strike its strings with small rubber tips, the tone taken from the strings by pickups, damped and soft, each note stopping when its key is let go; and a **crumhorn**, played softly and low in its range, its double reed shut inside a wind cap, so the player's breath reaches the reed only through the cap, and it can't overblow past its range. No other film on the site uses either; no maker is named. Both are made in the film's own `tools/score.py`, with a small, dry room round them, and low-passed, so nothing rings above about 2.5 kHz.

- **The mark is the same for a person and for an agent.** Four notes, B flat, E flat, D flat, G flat. Anil's key plays it on the clavichord alone, as the key settles on the hook and the agent signs in as him. The two play it again over the title card, then when Clara and the agent read the staff table the same way, and on "One set of rules for people and agents": four times in all, twice after the opening. ## Rigour to check before recording

Checked on 4 November 2026 on docs.databricks.com (AWS); the sources are listed below. Product names and maturity are the docs' on that day.

- **Unity Gateway, not AI Gateway.** Databricks' release notes for Unity Gateway, 4 August 2026: "Unity Gateway is now generally available. Unity Gateway is the Databricks governance solution for enterprise AI, part of Unity Catalog." and "Some capabilities, including service policies and agent services, remain in Beta." The AI governance guide: "Unity Gateway and Unity Catalog asset governance are generally available. Service policies are in Beta". The name "Unity AI Gateway" is from a community post of 22 May 2026, while it was in beta, and no doc page on the day uses it; the workspace's sidebar still says "AI Gateway". The plan's working title said "AI Gateway"; the film says "Unity Gateway", once glossed as "its gate to models", and the folder keeps its name, `8-unity-catalog-and-ai-gateway`.
- **"His personal key: a code that lets software sign in as him."** Databricks, *Authenticate with Databricks personal access tokens (legacy)*: a token is "for the Databricks user account or Databricks service principal"; without a scope it grants "full workspace access (the `all-apis` scope)"; scopes "restrict a token's permissions to specific API operations", not to tables, so through SQL it still reads what its owner can; "Where possible, Databricks recommends using OAuth instead of PATs for user account authentication because OAuth provides stronger security." The film's "a personal key can't hand over less than everything he has" means his data: no token he makes can read less than he can. "Databricks automatically revokes PATs that haven't been used for 90 days": a key an agent uses every night never lapses. "Another key of his" for the model is the same kind of token, or a model provider's key in his name; the film doesn't say which, and "Anil's keys are taken back" takes back both.
- **The log.** `system.access.audit`, in Public Preview, keeps a year; a read is a `getTable` event (the project's `docs/databricks-governance.md`, section 6, and `analyses/governance/who_read_a_table.sql`, which selects `event_time, user_identity.email` for the staff table this month). Reads made with Anil's token are his in the log, under his address; a service principal's are under its application ID, which the film shows shortened, "7c41e09a-…", with its name beside it. The film's "2,300 times" on one Sunday night is invented and small for an agent that answers a week's questions with several queries each. The log is called "in preview" once, in *A rule it's told, and a rule that holds*, as *Governed in Unity Catalog* calls it.
- **A person's sign-in, or a name of its own.** *Agent authentication*, for agents on Databricks Apps: "App authorization" (the agent's own service principal, the default) and "User authorization" (on behalf of the user who asks, Public Preview, with that user's row filters and column masks). The film's "An agent that helps one person, while they're there, can use that person's sign-in" is the second, as *Working with agents on Databricks* shows Anil's agent signed in as him; the workload agent works at night, for no one in particular, so it has its own.
- **Service principals.** *Service principals*: "You can grant and restrict a service principal's access to resources in the same way as you can a Databricks user". *Manage service principals*: "You can deactivate a service principal at either the account or workspace level. Deactivation prevents the service principal from authenticating and accessing Databricks APIs, but does not remove its permissions or objects", and "When reactivated, the service principal regains access with the same permissions." The film's "switches off its service principal" is deactivation. The project's `AGENTS.md`, *Your access*: "On Databricks, you work as your own service principal, never as a person. It can read production and write only to its own development schema", and its grants go to `<agent service principal>`; *An agent on the team* says it the same way. The workload agent's grants on the two HR tables are the Faculty of Health's, drawn for the film, and section 9 of the project's platform guide writes them the same way.
- **Grants, to the agent's own name.** *Governed in Unity Catalog*: "Who may read a table is a grant, and a grant goes to a group, never to a person". A service principal isn't a person: it's one identity for one job, and the project grants to it directly, as the film does ("grants it only what its job needs"). The film shows no group for the agent, so it never says a group's grants are the agent's.
- **The same masks.** The project's section 3 creates `mask_direct_personal_data` "on catalog …, with the mask, to `account users` except the readers". *Groups*: "Each account includes an `account users` group containing all users and service principals." ABAC's policies page: "The `TO` clause specifies the users, groups, or service principals subject to the policy." So the agent outside the readers' group reads `***`, as Clara does (*Governed in Unity Catalog*: "Clara reads the learner table, and sees each learner's status, and stars where the names and emails are"; the film shows her the staff table the same way). "Nobody wrote a rule for agents" is true of the project: its policy names no agent. The "HR and faculty offices" group on screen stands for the readers' group of section 3 (`personal_data_readers`), which Anil, who runs a faculty's office, is in.
- **Row filters.** ABAC policies can filter rows as well as mask columns, with the same `TO` clause (*Governed in Unity Catalog*: "A policy can filter rows the same way; this one masks"). The project has no row filter: the faculty table in pencil is "a sketch", and `health_readers` is the film's; it claims only that a filter for a group applies to an agent in it.
- **The staff code.** The HR source tags `staff_bk`, the staff ID, and the names, birth date, country of birth and email `direct` (`models/staging/hr_system/_hr_system__models.yml`); `staff_key`, the hash of `staff_bk`, isn't tagged, so section 3's policy leaves it readable, and an agent can count people by it without a name. The film calls it "the staff code". "Nursing · this term · 64 teachers · 38 of them casual" is invented, an answer of the kind the HR contracts give: each contract has a position type (`Academic` or `Casual Academic`), a unit and a teaching period (`data/hr_system/contracts.csv`). The 168 active projects in Health are *Working with agents on Databricks*'s count (the series' `numbers.md`), and its green pill, "Matches the source", is that film's.
- **Functions as tools.** *Create a custom tool*: "Use Unity Catalog functions when your agent needs to run predefined logic", and "calling an existing function requires `EXECUTE` on it". The AI governance guide: "Unity Catalog also governs the functions that agents use as tools, with the same privileges." Changing a function takes its ownership (or `MANAGE`), which the project check agent doesn't have. `active_projects(faculty)` is *Working with agents on Databricks*'s, in the example project (`examples/agents-on-databricks/active_projects.sql`), written by the data team, reviewed by Jun and approved by Noor; the film says "the data team wrote once", and its owner tag says "data team". It doesn't claim whose privileges its body runs with.
- **Tool servers.** *Govern an MCP*: external MCP servers are registered as Unity Catalog MCP services; "Callers need `EXECUTE` on the MCP, `USE CATALOG` and `USE SCHEMA` on its parents". Databricks' own managed MCP servers are catalog objects too (`system.ai.*`), Genie One's generally available and the others needing the Unity Gateway beta; the workspace's MCP endpoints, in Public Preview, don't go through the gateway. The film's tool servers are the team's, registered through Unity Gateway, and only read (the module's rule). The names on their cards, "Catalog", "Query" and "Repository", are the film's; "not granted" means the workload agent has no `EXECUTE` on the third.
- **Models.** *Model services*: "By default, only the model service owner can query it. To let others query a model service, grant them `EXECUTE` on it, plus `USE CATALOG` and `USE SCHEMA` on its catalog and schema." A model service is a catalog object (catalog.schema.name). The film names no model and no provider.
- **Checks, in beta.** *Service policies for AI securables* (Beta, page updated 29 October 2026): built-in policies under `system.ai`, among them `system.ai.detect_sensitive_data`, which "detects structured sensitive data (such as credit card numbers and Social Security numbers) and either blocks the interaction or redacts the matched values", and `system.ai.block_jailbreak`, which "detects jailbreak and prompt-injection content", and on MCP services "can evaluate the tool call and arguments on input, the tool result on output, or both". *Detect sensitive data* (Beta, updated 19 October 2026) lists 15 categories, among them `class.email_address`; "Names, locations, and organizations" are not detected. So the film's check finds "an email address", never a name, and "hides it or stops the call" is redact or block. The pills say "sensitive data" and "prompt injection", and not "beta": since 5 November 2026 no film says a feature's release status, which changes (the author). A blocked call returns a successful response that names the policy; the film's "blocked" and "hidden" are its own words, not the product's screen.
- **Limits and usage.** *Rate limits*: limits in queries or tokens a minute, for "Individual users or service principals", user groups, or a default per user; the film's "60 calls a minute" is invented. *Usage tracking*: `system.ai_gateway.usage` records each call with its requester (a user or a service principal) and its tokens; the AI governance guide: "Analyze cost across models, principals, and tags." So the Faculty of Health can see what its agent costs; "about 300 dollars a month" is invented. The film doesn't say the gateway sets a budget for one agent: a budget that stops an agent is *A colleague that isn't a person*'s.
- **Lineage.** *Lineage system tables*: "The table lineage system table includes a record for each read or write event on a Unity Catalog table or path", from "Lakeflow pipelines, notebooks, jobs, Databricks SQL queries, dashboards, Genie Agents, and alerts"; `created_by` "can be a Databricks username, a Databricks service principal ID"; "Records are only emitted when lineage can be inferred." The film's "Lineage shows the tables its queries read" is a read event's lineage. `stg_hr_system__staff` and `stg_hr_system__contracts` are the project's HR staging models, drawn as the tables an answer about Nursing's teachers would read.
- **A rule it's told.** The project's `AGENTS.md`, *What you must not do*: "Never copy names, emails or student IDs out of the project, into a prompt, a log or a pull request, beyond the sample a claim needs." The page on screen quotes it whole; the narration says the first part. "Talked out of it by words hidden in what it reads" is prompt injection (OWASP's agentic top 10; `system.ai.block_jailbreak` above).
- **What it builds on, quoted as merged.** *Working with agents on Databricks*'s last question, "when an agent reads on its own, whose reads are they, and who pays for its model?", is its thread's line on 4 November 2026; if that film's final words change, this film's opening still answers them. *Why we govern them*: "To work for the team, it needs a name of its own"; its badge there says "census agent"; since *Working with agents on Databricks* gave Jun's agent the nightly check of research projects, this film calls it the "project check agent".
