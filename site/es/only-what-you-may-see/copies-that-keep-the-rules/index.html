Copias que mantienen las reglas: protegidas, o no se hacen

Este otoño se piden cuatro copias de los expedientes: una para construir, una para el hospital universitario, una respuesta que pide las filas de ambos y una para llevar a casa. Las reglas viven en el catálogo, no en los expedientes: cada copia mantiene la protección, o no se hace.

Lee la guía por tu cuenta

La película muestra Azure Databricks y dbt como los describían sus documentos el 10 de noviembre de 2026. Estas son las páginas que sigue.

  • Azure Databricks: OpenSharing y ABACPor qué quien comparte una tabla protegida debe quedar fuera de sus políticas, y por qué quien la recibe ve entonces cada valor, salvo que aplique políticas propias.
  • Azure Databricks: requisitos y límites de las políticasNo se permiten clones de una tabla con políticas, salvo para alguien que todas las políticas excluyen, y que ve cada valor sin máscara.
  • Azure Databricks: ¿qué son las salas limpias?Socios trabajan juntos sobre datos sensibles sin ver las filas del otro: cada uno ve solo los nombres y tipos de las columnas del otro.
  • Azure Databricks: ejecutar cuadernos en salas limpiasCada colaborador, salvo quien lo subió, aprueba un cuaderno antes de que corra, y solo quien este designa puede ejecutarlo.
  • Azure Databricks: acceso a las funciones del cuadernoLos interruptores del espacio de trabajo para descargar resultados, exportar cuadernos y copiar tablas al portapapeles, que empiezan encendidos.
  • Azure Databricks: control de salida sin servidorUna política de red que deja a lo que corre sin servidor llegar solo al almacenamiento del catálogo y a los lugares de una lista corta.
  • dbt: pruebas unitarias (en inglés)Probar la lógica de un modelo con unas pocas filas escritas para la prueba, sin necesitar datos reales.
