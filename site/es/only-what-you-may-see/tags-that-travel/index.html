Etiquetas que viajan: una clase puesta una vez, en todas partes

Mei nombró una clase para cada columna de la tabla de estudiantes. La plataforma tiene que leerlas, y cada tabla hecha a partir de ella tiene que llevarlas, o una copia muestra lo que su origen oculta. ¿Cómo se vuelven etiquetas en Databricks y dbt, y siguen a los datos por sí solas?

Lee la guía por tu cuenta

La película muestra Azure Databricks, dbt y GitHub como los mostraba su documentación en noviembre de 2026. Estas son las páginas que sigue.

  • Etiquetas gobernadasAzure Databricks: una etiqueta con sus valores permitidos y una política de quién puede asignarla, así solo se ponen esos valores, y solo quien puede.
  • Propagación de etiquetasAzure Databricks: una etiqueta gobernada llevada por el linaje a las tablas y vistas hechas de una columna etiquetada, y el valor por defecto donde se encuentran dos.
  • Clasificación de datosAzure Databricks: un escaneo de los catálogos elegidos que propone clases para las columnas que reconoce, como un nombre o un correo, para que sus dueños las revisen.
  • Linaje en Unity CatalogAzure Databricks: el registro de la plataforma de lo que leyó cada consulta y lo que hizo, hasta la columna, que sigue la propagación de etiquetas.
  • meta (en inglés)dbt: la configuración meta, donde el proyecto escribe la clase de cada columna junto a ella, en el archivo YAML del modelo.
  • pre-hook y post-hook (en inglés)dbt: SQL que corre antes o después de construir un modelo, como los hooks del proyecto que ponen cada clase, la etiqueta de facultad y el nivel.
