## The promise

Every line passes two tests: someone who has only heard of AI agents can follow it, and a data governance lead and a platform engineer who runs agents on Databricks each find nothing wrong in it. The series began with what an agent reads (*Context engineering*), and this last film closes the circle: what an agent reads shapes what it does, so it is data, and gets what any data gets: an owner, who may read it and who may change it, a review before agents use it, a time to keep it, and a way to delete it everywhere it's kept. The team's context already lives in its repository, reviewed like code, and goes one way to where agents read it. Memory is different, because agents write it themselves: kept in a store anyone with write access can change, and distilled by a daily step that asks no one, a right lesson can lose the words that made it right, and nobody sees. So the team keeps the daily step's output as proposals, which a person confirms and an owner approves as files in the repository, and only then loads them where agents read. The film is about governing what agents read; what an agent reads is *Context engineering*'s, how a lesson becomes the team's is *Memory: from one chat to the team*'s, and an agent's own identity and rights on the platform are *Why Unity Catalog and Unity Gateway govern them*'s. **The team's context and memory are governed assets, not private notes.**

## The story in one paragraph

Today, at the university: Lucía Ortega joined the Planning team on Monday. Her agent starts each day with the team's memory, lessons its agents learned, approved by people. Her first job is for the library: how many students are there, to buy next year's e-books? Her agent drafts 18,026, and a plain check against the census report, which says 18,412, stops it. The 386 it left out all study online, and the library would have bought e-books for 386 fewer students, the very ones who can't come in for a book. The agent's evidence shows why: one line in the team's memory, "Count only students on campus". In May it was approved as "For exam rooms, count only students on campus", right for rooms; since last week it had lost the three words that made it right, nobody saw it change, and every agent still read it, for questions no report could check. So the team now governs its context and memory as it governs any data: each has an owner, agents may read them and never change them, a person reviews every change, and each is kept only while it's right, then deleted from everywhere it's kept. Checked against its source, the line is found and deleted, with a record of why. Lucía's agent now starts from what the team knows, every entry with who approved it, and the library buys for all 18,412. The film then goes back over what an agent reads, the series' four kinds of context and memory, and the five questions any data must answer; the team's context, kept in its repository and reviewed like code, going one way to Unity Catalog and Unity Gateway, where nobody edits it; its memory, in stores in Lakebase, where a daily step merged the campus line with other lines, as it's built to, in a store where whoever may write may change any entry and nothing records what it said before; the store split in two, the daily step writing only proposals, a morning pull request with one file for each, confirmed by the person whose session it came from and approved by the owner of its meaning, Yusuf in data governance owning the memory as a whole, and a script loading the approved files into a store every agent may read and none may change. Keeping and deleting are decisions too: sessions kept thirty days, a date on each entry to check it again, no student named in a lesson; and deleting has traps, since deleting a chat deletes nothing of what was kept from it, and the skill sync never deletes, so the team deletes where a thing is kept, with a record. Asked again, Lucía's agent answers 18,412 with its evidence, and the series closes on its nine lessons and the road ahead: *From helper to colleague*.

### 4 · Memory, kept like data · 3:58–5:16

**Narration.** Memory is different: agents write it themselves. On Databricks, sessions and lasting memory are kept in stores in Lakebase, the platform's database. A step that runs once a day reads the sessions, and keeps what seems worth keeping, without asking anyone. That's how the campus line lost its words: the step merged it with other lines about counting students, as it's built to. And a store is one room: whoever may write to it may change any entry, and nothing records what an entry said before. So the team split it in two. The daily step now writes only proposals, which no agent reads. Each morning, a script brings them to the repository as a pull request, one file for each entry. The person whose session it came from confirms what they meant, and the owner of its meaning approves it. Yusuf, in data governance, owns the memory as a whole. Then a script loads the approved files into the team's store, which every agent may read, and none may change.
