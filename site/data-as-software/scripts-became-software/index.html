Scripts became software: tested, reviewed, released

Every second Thursday, Rohan in Finance needs what casual staff are paid. For years a script on one person's laptop told him, until the claims moved in February and nobody could change it safely. Sam and Jun move it into the data project: tested, reviewed by someone else, released the same way.

Go further in the official docs

The film names the ideas and shows them once. The docs show how, and stay current as the tools change: start there, adapt what fits, and iterate.

  • What are Declarative Automation Bundles?Databricks: a project's jobs, and where each one runs, written as files and deployed the same way to every target. Formerly Databricks Asset Bundles.
  • Deployment modesDatabricks: how a bundle deploys to development, and to production, where nobody runs it as themselves.
  • Specify a run identityDatabricks: a job that runs as the platform's own account, never a person's.
  • Use dbt transformations in Lakeflow JobsDatabricks: a job with a dbt task that builds and tests the models it reads.
  • Unit testsdbt: a model's logic tested on rows you write, such as a rule's edge, before it runs on real data.
  • Add data tests to your DAGdbt: tests on the data itself, run every time the project builds.
  • About protected branchesGitHub: nothing merges without a review by someone other than its author, and every check green.
  • Managing environments for deploymentGitHub: a release that waits for a named person's approval before it reaches production.
