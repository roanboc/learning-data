Network, storage and keys: one door to the data

Production's files sit in Azure storage, and Unity Catalog is meant to be the only way to them. Sam Okafor finds nine ways around it: two account keys, a link signed with one, and six people with a role on the storage. Every door is open to the internet. He shuts all but one.

Read the guidance yourself

The film shows Azure Databricks and Azure Storage as their docs did on 5 November 2026. These are the pages it follows, one for each path it closes and for the key; links checked on 10 November 2026.

  • Private Link conceptsThe private doors in: from people to the workspace, and from the machines that run the jobs to Databricks.
  • Manage IP access listsLet in only known addresses while a public door remains, and what changes once there's a private one.
  • What is serverless egress control?A network policy with restricted access, so data leaves only for places on the list, tried first in dry run.
  • Prevent authorization with Shared KeySwitch off a storage account's keys, so nothing signed with them, a link included, opens a file again.
  • Use Azure managed identities in Unity Catalog to access storageThe access connector: the catalog's own identity at the files, with no secret anyone holds.
  • Workspace-catalog bindingBind each catalog to its own workspace, so from any other a grant isn't enough.
  • Customer-managed keys for encryptionA key of your own for the workspace's notebooks, queries and disks, and what happens if it's taken back.
  • Customer-managed keys for account encryptionThe storage's own key, kept in a vault: the storage uses it, and picks up each new version.
